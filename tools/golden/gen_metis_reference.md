# METIS reference goldens (WP-AD.2 Stage A)

The `dss-metis` crate is a 1:1 safe-Rust source port of the METIS 5.2.1
`METIS_PartGraphKway` path (`DIAKOPTICS_PSTCALC_PLAN.md` D2). Its bit-exact gate
compares the port against the **C original**, built OFFLINE on the dev machine.
No C is compiled in `cargo test` or CI — the `.graph` fixtures and `.part.N`
outputs under `crates/dss-metis/tests/golden/` are committed artifacts,
regenerated only manually by the procedure below (the dss-python-goldens
discipline).

This file documents the exact toolchain, flags, seed, type widths, and command
lines so the goldens are reproducible.

## Spec pins (D2)

- `.inputs/METIS` @ `272d4a9` (KarypisLab/METIS `origin/master` = release
  `v5.2.1` + 39 bit-identical post-release commits).
- `.inputs/GKlib` @ `3b7d61b` (KarypisLab/GKlib).

## Toolchain (this machine, 2026-07-11)

- Compiler: MinGW-W64 `gcc.exe (…ucrt…r8) 13.2.0` at `C:\Strawberry\c\bin`.
- CMake 3.29.2, GNU Make 4.4.1 (`mingw32-make`), generator `"MinGW Makefiles"`.
- Build performed OUT OF the pinned tree: `.inputs/METIS` and `.inputs/GKlib`
  are copied to a scratch dir and built there (never modify `.inputs`).

## Type widths

METIS 5.2.1 default build: `IDXTYPEWIDTH=32`, `REALTYPEWIDTH=32`. The port
matches: `Idx = i32`, `Real = f32`. The widths are written into
`build/xinclude/metis.h` at configure time (see below).

## Build steps

```sh
SCRATCH=<scratchpad>/metis-build          # out-of-tree copies of the pinned spec
PREFIX=$SCRATCH/install
cp -r .inputs/GKlib  $SCRATCH/GKlib
cp -r .inputs/METIS  $SCRATCH/METIS

# 1) GKlib with the portable RNG (USE_GKRAND) -> deterministic, platform-independent.
cmake -S $SCRATCH/GKlib -B $SCRATCH/GKlib/build -G "MinGW Makefiles" \
      -DCMAKE_C_COMPILER=gcc -DGKRAND=ON -DGKLIB_BUILD_APPS=OFF \
      -DCMAKE_INSTALL_PREFIX=$PREFIX -DCMAKE_BUILD_TYPE=Release
cmake --build $SCRATCH/GKlib/build --target install

# 2) METIS: generate the width header exactly as `make config` does, then configure.
mkdir -p $SCRATCH/METIS/build/xinclude
printf '#define IDXTYPEWIDTH 32\n#define REALTYPEWIDTH 32\n' > $SCRATCH/METIS/build/xinclude/metis.h
cat $SCRATCH/METIS/include/metis.h  >> $SCRATCH/METIS/build/xinclude/metis.h
cp  $SCRATCH/METIS/include/CMakeLists.txt $SCRATCH/METIS/build/xinclude/
cmake -S $SCRATCH/METIS -B $SCRATCH/METIS/cmbuild -G "MinGW Makefiles" \
      -DCMAKE_C_COMPILER=gcc -DGKLIB_PATH=$PREFIX -DCMAKE_INSTALL_PREFIX=$PREFIX \
      -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_C_FLAGS="-D__USE_MINGW_ANSI_STDIO=1 -Wno-error"
cmake --build $SCRATCH/METIS/cmbuild        # builds libmetis/libmetis.a
```

Notes:
- `-D__USE_MINGW_ANSI_STDIO=1 -Wno-error` only silences MinGW `%zu`/`getrusage`
  format-warnings-as-errors in **debug/print** paths; they never touch the
  partition numbers.
- The stock `gpmetis` CLI does not build on Windows (`getrusage`); we link a
  minimal driver instead (allowed by the WP brief). `libmetis.a` builds cleanly.

## Golden driver (== `gpmetis <graph> <nparts>` with CLI defaults)

`driver.c` (in the scratch build dir, not committed) replicates:
- `programs/io.c::ReadGraph` (standard 1-based METIS format);
- the exact option assignments of `programs/gpmetis.c` main() for the KWAY path
  with `cmdline_gpmetis.c` defaults: OBJTYPE=CUT, CTYPE=SHEM, IPTYPE=METISRB,
  RTYPE=GREEDY, NO2HOP=0, MINCONN=CONTIG=ONDISK=DROPEDGES=0, SEED=-1,
  NIPARTS=-1, NITER=10, NCUTS=1, UFACTOR=-1;
- `METIS_PartGraphKway(...)` then `WritePartition` format (`%d\n` per vertex).

```sh
gcc -O2 -I$PREFIX/include -I$SCRATCH/METIS/build/xinclude driver.c \
    $SCRATCH/METIS/cmbuild/libmetis/libmetis.a $PREFIX/lib/libGKlib.a -lm -o driver.exe
```

`SEED=-1` -> `InitRandom(-1)` -> `isrand(4321)` (`libmetis/util.c:23`), so the MT
is seeded with **4321** and the result is deterministic (verified identical
across repeated runs).

## Fixtures

Committed under `crates/dss-metis/tests/golden/` (all standard 1-based METIS,
symmetric, `fmt=1` edge weights = phase counts 1/2/3):

- `radial12`, `radial40`, `radial200` — synthesized radial feeders (spanning
  tree + a few laterals), and `mesh120` — a 10x12 meshed grid. Generated by
  `scratchpad/gen_fixtures.py` (deterministic seeds), committed as fixtures.
- `ckt24norm` — normalized from the official OpenDSS artifact
  `tests/golden/provenance/ckt24_openDSS_raw.graph`
  (`…/ADiakoptics/ckt24/ckt24_.graph`). The official file is 0-based with the
  OpenDSS `Create_MeTIS_graph` line/index quirks (Stage-B concerns); `ckt24norm`
  is its topology re-emitted as a valid symmetric 1-based standard METIS graph
  so the stock C reader accepts it. Provenance kept alongside.

## Generating the `.part.N` goldens

```sh
for g in radial12 radial40 radial200 mesh120 ckt24norm; do
  for k in 2 3 4 8; do driver.exe $g.graph $k; done   # writes $g.graph.part.$k
done
```

Commit the resulting `*.graph.part.{2,3,4,8}` next to the fixtures.

## RNG harvest (pins `dss_metis::rng` bit-exact)

`rngprobe.c` links `libGKlib.a` and prints the raw generator streams after
`gk_randinit(seed)`:

```sh
gcc -O2 -I$PREFIX/include rngprobe.c $PREFIX/lib/libGKlib.a -lm -o rngprobe.exe
rngprobe.exe    # randint32/randint64/randInRange(1000) @ seed 4321, randint32 @ seed 123
```

The first 20 values of each stream are pinned as constants in
`crates/dss-metis/src/rng.rs` (`#[cfg(test)]`), asserted bit-exact by the unit
tests. Seed 4321 is METIS's `SEED=-1` default; seed 123 is the
`parmetis`/`ometis` fixed seed, harvested for coverage.

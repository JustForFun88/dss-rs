# Test corpus

The decks the unified live corpus gate (`crates/dss-core/tests/corpus_gate.rs`)
runs on this engine and the OpenDSS engines.

## `electricdss-tst/` — the OpenDSS test suite, fetched

Not in git. `python tools/corpus/vendor.py` fetches the commit `PIN.json` names
from github.com/dss-extensions/electricdss-tst into this gitignored directory,
with LF line ends in text files, and checks every file against `SHA256SUMS`.
`corpus_hygiene.rs` fails while the tree holds another commit than the pin.
Relative paths are kept, so masters resolve their `redirect`/`compile` data
dependencies with no path rewrites.

No test writes here: a case whose deck writes files runs from a scratch copy. A
manual run of a deck executes it *in place*, so OpenDSS writes outputs
(EnergyMeter `DI_*.csv`, exports, `LineConstantsCode.dss`, …) into this tree.
Probe a copy of a deck instead, or run `python tools/corpus/vendor.py` afterwards:
it lists and undoes what the run wrote.

Every `.dss` file here is accounted for in exactly one manifest under
`tests/corpus/manifests/` — enforced by `corpus_manifest.rs`.

## Synthetic deck families (in git)

Besides the fetched `electricdss-tst/`, three **hand-written /
generated** deck families live here, each with its own `manifest.json`, a
structural `<family>_manifest_is_complete` gate, and live comparison inside the
unified `corpus_gate_all_cases_match_engines` test
(`crates/dss-core/tests/corpus_gate.rs`):

- `asymmetric/` — static/snapshot element coverage in deliberately
  asymmetric configurations (the transposed-YPrim-stamp class);
- `controls/` — control / protection / metering elements with per-step state
  channels (probes, event log, control queue, meters/monitors);
- `modes/` — solve modes, solution algorithms, input formats, executive
  verbs (Monte Carlo, load-duration, Time, AutoAdd, Newton, binary/CSV
  shapes, harmonics-mode decks, BatchEdit, Reduce, fault study).

A case with `pending: true` covers a feature this engine does not implement yet:
the gate asserts the Rust engine errors **loudly** on it, and its `wp` field
names the work that implements the feature and flips the flag. A
case needing more than one file lives in a subfolder named after the deck
(e.g. `modes/inputformat/shape_binfiles/`).

## `props_r4133/` — frozen evidence, not decks

The one subdirectory here that holds no `.dss` file and no manifest: the
vendored **r4133 property census** —
five byte-identical copies of extracts whose source is local-only, plus five
derivations of a 270 MiB census that stays out of the repo (pair / bin /
example / in-scope tables). Read `props_r4133/README.md` before using any of it:
it carries the provenance, the parse rule, the bin rule, the in-scope filter and
the data traps. The bytes are locked by
`crates/dss-core/tests/props_r4133_evidence_lock.rs`; `.gitattributes` marks the
subtree `-text` so no checkout rewrites it; nothing there is regenerated by
`cargo test` (re-measurement is the `DSS_PROPS_CENSUS` knob).

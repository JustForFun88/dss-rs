# Test-triage: Monitor modes 8 / 10 / 12 — finish the port (wt-t3)

Backlog item: "Monitor modes 8/10/12 (winding currents / winding voltages /
line-line) — finish the port." Before this change the header path
(`monitor/header.rs`) declared `record_size` for modes 8/10/12 but
`TakeSample` had a deferred stub (`_ => return`) — a monitor in those modes
sampled a **timestamp-only** row, so `channel()` read out of bounds (stride =
`record_size + 2` but only 2 values written) → panic / wrong data.

## What landed (1:1 port, `Meters/Monitor.pas` = spec, byte-identical r4088=r4133)

`elements/meter/monitor/sample.rs` — the three `TakeSample` bodies:

- **Mode 8 — winding currents** (`Monitor.pas:1311`): downcast the metered
  element to `Transformer`, refresh `cd.vterminal` (Pascal reloads it inside
  `GetAllWindingCurrents`; the `&self` Rust getter reads the caller-populated
  buffer, so refresh first as mode 11 does), call `get_all_winding_currents`
  (`2·Nphases·NumWindings` complex, both ends of each winding), convert the
  whole buffer to polar, then store every *other* entry's (mag, angle) — the
  magnitude is identical at each end (`k := 1; k += 2`).
- **Mode 10 — winding voltages** (`Monitor.pas:1337`): for each winding call
  `get_winding_voltages` (fills `PhsVoltagesBuffer[1..Nphases]`), scatter into
  `WdgVoltagesBuffer[i + (j-1)·NumWindings]` (winding-minor within each phase,
  matching the `P{phase}W{winding}` header), convert `NumWindings·Nphases`
  entries to polar, store all as (mag, angle) pairs.
- **Mode 12 — line-to-line terminal voltages + currents** (`Monitor.pas:1374`):
  per terminal, extract that terminal's phase voltages, plant `V[1]` at the
  reference slot (`NPhases+1` if `NPhases=NConds`, else `NConds`) so the last
  phase wraps, form the LL differences, convert to polar, store `2·NPhases`
  doubles; then the full terminal currents (`2·MeteredElement.Yorder`).

`transformer/yterminal.rs::get_all_winding_currents` promoted to `pub(crate)`.
The P2 `MonitorBaseMode::Undefined` arm (ordinals 13/14/15) stays `=> return`
(Pascal `else Exit` = timestamp-only row). `monitor/mod.rs` module doc updated
to list 8/10/12 as ported.

## Header parity

Verified against `ClearMonitorStream` (`Monitor.pas:773-846`). Modes 8/10 share
the phase-major/winding-minor `P{i}W{j}` + `Deg` header; mode 12 emits
`V{a}-{b}T{j}` LL labels + `I{i}T{j}` currents. Already correct in
`header.rs` (built during wave-1 P2); no change needed.

## Upstream UB found and gated around (NOT reproduced)

Mode 12's current section is an **uninitialized-heap read** for any element with
`NTerms > 1`: the fill loop `for i := 1 to Yorder` uses the *monitor's own*
`Yorder` (= `Nconds`, because a monitor always has `Nterms = 1`,
`Monitor.pas:458`) while `ConvertComplexArrayToPolar`/`AddDblsToBuffer` run over
`MeteredElement.Yorder` (= `Nconds·NTerms`). Terminals 2..N are read from
`ReallocMem`'d (non-zeroed) heap. Proven nondeterministic: identical circuit +
identical solve, terminal-1 currents byte-identical, but terminal-2 currents flip
between `0.0`, `inf`, `nan`, and nonzero garbage purely from unrelated prior
monitor allocations. Per CLAUDE.md (UB documented + gated around, never
reproduced) the port fills all `MeteredElement.Yorder` currents correctly.
Full write-up: `investigations/monitor_mode12_terminal_currents_ub.md`.

Mode 12 on a **single-terminal** element (Load/Generator/Capacitor) has no UB
region (`monitor Yorder == MeteredElement.Yorder`) and matches the oracle
exactly — that is what the golden pins.

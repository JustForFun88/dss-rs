## Surprises — real non-protection r4088→r4133 divergences (NOT predicted)

`delta_r4088_r4133.md` claims the solver, PCElements, and Meters are
**byte-identical** r4088=r4133; only protection moves. The sweep found two
non-protection numeric divergences. **Determinism-probed:** `oddie:r4088 ↔
oddie:r4088` and `oddie:r4133 ↔ oddie:r4133` both **match** on these cases, so
each engine is deterministic and the r4088≠r4133 difference is a **real,
reproducible engine output change**, not run-to-run noise.

1. **`IEEE_519` harmonics** (`HarmonicsTMode/` + `HarmonicsVariableLoad/`):
   V **1.316e-2** / 7.463e-3 @ pcc.2 with the **assembled Y bit-identical**
   (Yf = 0). A harmonics-mode result move over an identical model. In
   `capi015↔r4088` the same deck agrees to V 8e-5, so this is squarely an
   r4088→r4133 move.
2. **`InductionMachine` `Master.DSS`/`Run.dss`**: `converged True vs False`,
   Y-fingerprint 0.05 / 0.89 — a convergence outcome flip.

**Interpretation (unresolved at inventory scope):** the directory-diff behind
`delta_r4088_r4133.md` shows no source hunk in these paths, so the cause is
either (a) an un-diffed harmonics/induction-machine change, or (b) Delphi
build-to-build last-ulp drift amplified by ill-conditioning (harmonics near a
519-filter resonance; a marginal IM fixed point). Both are consistent with
"deterministic per engine, differs across builds." A row is added to
`delta_r4088_r4133.md` bucket B; **WP-U2.6 must source-confirm or catalog** these
before claiming clean r4133 parity (they are not protection, so they do not
belong to any Rung-2 protection WP).

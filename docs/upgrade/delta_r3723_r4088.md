## Бакет A — новые классы элементов / режимы решения / команды

### A1. Решатель NCIM (N-Conductor Current Injection Method) — `Common/Solution.pas` (~1300 новых строк из диффа 1905) + сателлиты
Newton–Raphson-подобный power flow в прямоугольных координатах (инъекции тока; ссылка на статью S0142061512004310). Активация: `Set Algorithm=NCIM` (`Utilities.InterpretSolveAlg`: префикс `'nc'` → `NCIMSOLVE = 2`; диспетчеризация `DoPFLOWsolution → DoNCIMSolution`). Новые процедуры/поля `TSolutionObj`: `InitNCIM`, `LoadYBusNCIM` (Y через `GetTripletMatrix`), `BuildJacobian`, `CalcInjCurr`, `GetNCIMPowers`, `ApplyCurrNCIM`, `DoPVBusNCIM`/`DoPQBusNCIM`/`DoZBusNCIM`, `DOForceFlatStart`, `UpdateGenQ` (Q-лимиты, PV→PQ переключение, `PV2PQList`, кластеры `DistGenClusters`), `InitPQGen`; поля `deltaZ/deltaF/pNodePower/pGenPower/pNodeType/Jacobian/NCIMRdy/IgnoreQLimit/GenGainNCIM`. Классификация узлов: Load (model 2 → Z-bus, иначе PQ), Generator (model 3 → PV-шина с `GenVars.VTarget`, model 4 → PQ, иначе Z), Fault → Z; прочие PC-элементы игнорируются. `Converged()` — отдельная ветка по `Abs(deltaF[i].re) <= ConvergenceTolerance`. `CheckControls` при `SystemYChanged` в NCIM ставит `NCIMRdy := False` вместо `BuildYMatrix`. Сателлиты: `Ymatrix.pas` — новая опция сборки `PDE_ONLY = 3` (Y только из PD-элементов + SOURCE); `KLUSolve.pas` — новый импорт DLL `SetMatrixElement` (якобиан!); `generator.pas` — `NCIMIdx`, `InitPVBusJac`, override `GetCurrents` (при NCIM возвращает `ITerminal` напрямую); `GeneratorVars.deltaQNom`; `VSource.CalcInjCurrAtBus` (ток слэка по KCL через обход `getPDEatBus`/`getPCEatBus`); `PCElement.NumStateVars`.
**Численный эффект: да, только opt-in** (`Algorithm=NCIM`); дефолтные Normal/Newton пути байтово не изменены. **Вес порта: XL** (для dss-rs — отдельный решатель целиком; но чисто аддитивный).

### A2. WindGen — полная замена модели + новый `PCElements/WTG3_Model.pas` (1758 строк)
В r3723 WindGen был клоном Generator (синхронная машина + dispatch-шейпы). В r4088 это ветрогенератор GE Type-3 (DFIG) на новом объекте `WindModelDyn: TGE_WTG3_Model`:
- Свойства перенумерованы, `NumPropsThisClass` 41→44: удалены Xd/Xdp/Xdpp/H/D/Vpu/maxkvar/minkvar/forceon/status/ShaftModel/Balanced/XRdp; добавлены `Rthev, Xthev, Vss, Pss, Qss, vwind, QMode, SimMechFlg, APCFlg, QFlg, delt0, N_WTG, VV_Curve, Ag, Cp, Lamda, P, pd, PLoss, Rad, VCutIn, VCutOut`. **Деки WindGen из r3723 несовместимы.**
- `SetNominalGeneration`: LoadShape = кривая скорости ветра (не P-множитель); P из аэродинамики `Pm = 0.5·pd·π·Rad²·v³·Cp` − потери (`PLoss`-кривая), cut-in/cut-out, скольжение/разложение Ps/Pr; Q по `QMode` (0=Q, 1=PF, 2=volt-var по `VV_Curve`, IEEE 1547 CAT-B).
- Dynamics: весь машинный Тевенен-код заменён на `WindModelDyn.CalcDynamic/Init/Integrate`; `CalcYPrimMatrix` в Dynamics/Harmonics — Нортон конвертера `Cmplx(EPSILON, −N_WTG/(Xthev·WTGZLV))`.
- Переменные состояния 6 → `NumWGenVariables = 22`.
- `WTG3_Model.pas`: электрика (Тевенен за конвертером, ФАПЧ `PllLogic`, PI-регуляторы токов прямой и обратной последовательности, `CurrentLimiting` |I1|≤1.25, LVPL/LVQL, `FaultDetection`), механика (`CalcCp` — полином 5×5, `AeroMPPT`, `TorqueReg`, `PitchControl`, `APCLogic`, `WindInertia`, одномассовый `SwingModel`), собственный внутренний субцикл: нечётное число подшагов `delt0` (50 мкс) с трапецеидальным интегратором над 12 состояниями.
`WindGenVars.pas`: +поля `PLoss, ag, Cp, Lamda, Poles, pd, Rad, VCutin, VCutout, Pm, Ps, Pr, Pg, s`.
**Численный эффект: да — везде, где используется WindGen.** **Вес: XL.**

### A3. `Controls/pyControl.pas` — новый класс контроллера (410 строк) + инфраструктура DSSpyServer
`TpyControl` (`PY_CONTROLLER = 45*8`, регистрация в `DSSClassDefs`). Одно свойство `pyScript` (путь к .py). В `Sample` шлёт скрипт pyOpenDSS-серверу через named pipe (`\\.\pipe\...`); Python возвращает поток DSS-команд, исполняемых напрямую (`DSSExecutive.Command`), финальный `yes/no` решает пуш нулевой задержки в `ControlQueue`. Сервер запускается опцией `Set pyPath=...` (`DSSGlobals.Launch_PyServer` / `Write_2_PyServer` / `Read_From_PyServer`, `ShellExecuteEx` python.exe — Windows-only). Сопутствующее: `TPCElement.ForceY`/`ForceInjCurr`, публикация `CktElement.YPrim*` (protected→public), пропуск `CalcYPrim` в `Ymatrix.ReCalcAllYPrims` при `ForceY`.
**Численный эффект: только opt-in** (потенциально произвольный — скрипт исполняет любые команды). **Вес: M** (для dss-rs скорее «не портировать как есть» — архитектурное решение).

### A4. Новые команды — `Executive/ExecCommands.pas` (131→136)
`FirstObj`/`NextObj`/`CountObj`/`ActiveObj`/`ClassMembers` — итерация по активному классу (в паре с `set class=`). Плюс модификаторы: `Clear all` ≡ `ClearAll`; `Solve all` ≡ `SolveAll`; после `Solve` при `not Parallel_enabled` добавлен `Wait4Actors(ALL_ACTORS)` (Solve стал синхронным для внешних вызовов). Числа: нет. **Вес: S.**

### A5. Новые опции Set/Get — `Executive/ExecOptions.pas` (139→150)
`IgnoreGenQLimits` (139, NCIM), `NCIMQGain` (140, NCIM), `StateVar` (141 — set/get state-переменной Generator/WindGen/Storage напрямую — **пишет в модель, влияет на числа**), `pyPath` (142 — запуск py-сервера), `IterNumber` (143, get-only), `CtrlIterNumber` (144, get-only), `InjCurrent` (145 — set → `ForceInjCurr := True`, решатель использует внешние токи), `ITerminal` (146 — аналогично + `ITerminalUpdated`), `Yprim` (147 — set → `ForceY := True`, `SystemYChanged`), `IntegrationFlag` (148, get-only), `AllowForms`/`AllowProgressBar` (149/150, GUI). Опции 141/145–147 — крючки косимуляции: внешне заданные токи/Y подменяют модельные. **Вес: M** (сами опции S, но ForceInjCurr/ForceY-механика сквозная).

### A6. `General/CNTSLineConstants.pas` — новый класс + режим equivalent spacing
`TCNTSLineConstants` (наследник `TCableConstants`) заменяет `TCNLineConstants`/`TTSLineConstants` в LineGeometry: единый расчёт для **смешанных** линий CN + TS + голый провод (`FCondType`: 1=CN, 2=TS, иначе провод). Формулы Керстинга те же; для чистых CN/TS линий с `SemiconLayer=Yes` и детальным spacing результат идентичен старым классам. Новое: `FSemicon=No` — альтернативный знаменатель ёмкости (`ln(RadCN/RadIn) − (1/kStrand)·ln(kStrand·RadStrand/RadCN)`, «to match Synergi/Kersting»); ветки `FEquivalentSpacing`. **Вес: L** (вместе с A7/C-пакетом).

### A7. GenController исключён из регистрации — `Common/DSSClassDefs.pas`
`DSSClasses.New := TGenController.Create` закомментирован («up to date it does nothing», 03/2025). Дек с `New GenController.…` в r4088 падает «Object Class not found». Числа: нет (ошибка компиляции дека). **Вес: S.**

## Сверка со свипами WP-U0.2 (2026-07-11)

Этот документ — сырой Delphi-дифф r3723→r4088. Свипы напрямую r3723-бинарь не
гоняли; дельту r3723→r4088-эпохи эмпирически покрывают две пары (полный разбор —
`docs/upgrade/sweeps/`):

- **`capi(0.14.5=r3723) ↔ capi015(0.15.0b4≈r4103)`** — та же дельта на **FPC**-стороне
  (наша линия порта). Подтверждает витнесами: **B2 InvDynamics Isc1×1000**
  (`gfm_*`), **D1 SIMPLECARSON 658.85** (`Cable_constants`), **D5 InvControl**
  (`midi_invcontrol`), **B4/C7 RegControl реверс/idle** (`midi_controls` — рег-тапы
  меняются), **C1 `DblValueNZ`-клампинг → строгая ошибка по умолчанию** (16 деков
  падает в parse-error), **D14-класс DynamicExp** (`Dynamic_KundurDynExp`, V 0.87).
  Полностью совпадает с `delta_capi_0145_015x.md` (та же кодовая линия).
- **`capi015 ↔ oddie:r4088`** — FPC-vs-Delphi на линии r4088: **B5 SwtControl**,
  **D багфиксы контролов** видны как текст/дискретный порядок при идентичном
  электрическом состоянии (V≈1e-15) ⇒ логика совпадает, различается только
  форматирование логов (ledger `eventlog-trailing-space`/`monitor-header`).
  Реальный численный дрейф FPC-vs-Delphi — только `autotrans_both`/`midi_autotrans`
  (реглятор-тап `rat`, V 2–3e-2), `gendispatcher` (known `epri-gendispatcher-propname`),
  `Dynamic_KundurDynExp` (V 1.19).

**Атрибуция по рангам (свипы разводят):** протекционные деки (Relay/Recloser/Fuse/
SwtControl) в `capi015↔r4088` численно совпадают (только текст логов), а в
`r4088↔r4133` расходятся катастрофически — значит переработка защиты r4079–r4116,
которую 0.15.x **НЕ** портировала, целиком принадлежит **Рангу 2 (r4133)**, а не
r3723→r4088-дельте. B5 SwtControl (мгновенные действия) — единственная
протекционная позиция r3723→r4088, попавшая в 0.15.x, и она подтверждена как
Ранг-1.

**Без корпус-витнеса (синтезировать на своём WP):** A1 NCIM, A2 WindGen/WTG3,
A3/A5 pyControl-крючки, A6/B6/C2/C3 line-constants (equivalent spacing, EpsRmedium,
CNTS, SemiconLayer — дефолты совпадают), D8-r3723 zonelist. Подробности и WP-адреса
— в `delta_capi_0145_015x.md` §"WP-U0.2 sweep reconciliation".
